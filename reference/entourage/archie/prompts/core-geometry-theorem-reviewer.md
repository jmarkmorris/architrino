# Core Geometry Theorem Reviewer Prompt

Use this prompt when a single equation stack, theorem program, branch certificate, simulation diagnostic, or proof gap needs serious mathematical review.

Keep the request narrow. The target should be one document, one compact document stack, or one clearly named proof route.

## Context To Provide

Fill in these fields before sending the prompt:

- Target file or directory: `[PATH]`
- Main theorem, equation stack, branch certificate, or proof gap: `[TARGET]`
- Current objective: `[OBJECTIVE]`
- Preferred reviewer lens, if any: `[analysis / connection geometry / topology / invariants / statistical mechanics / relativity / field theory / structural maps]`
- Specific passages or equations to inspect first: `[PATH:LINE OR SECTION]`

## Prompt Body

Read the target material as a whole, but focus especially on `[TARGET]`.

Assess whether the current theorem program is mathematically coherent as a next-step program. Optimize for the next rigorous foothold, not a broad survey and not exposition polish.

Review questions:

1. Is the stated target theorem, certificate, diagnostic, or proof route mathematically coherent?
2. What is the single strongest next theorem target?
3. Which assumptions are explicit, and which assumptions are hidden?
4. Are the declared objects, domains, charts, connections, invariants, signs, and boundary conditions adequate?
5. Which parts are theorem-ready?
6. Which parts are plausible conjecture or heuristic only?
7. What additional hypotheses would make the target rigorous?
8. If possible, propose one theorem statement narrow enough to attack next and strong enough to materially advance the program.
9. Give a proof strategy sketch with the first nontrivial lemma or estimate.
10. Identify the durable capture path if the review succeeds: direct corpus promotion, priority staging, or no capture yet with reason.

## Constraints

- Stay anchored to the supplied documents and live repo conventions.
- Do not invent new ontology.
- Distinguish theorem-level statements, plausible conjectures, and heuristics.
- If a claim depends on assumptions not yet stated in the documents, say so explicitly.
- Prioritize equations, lemmas, invariants, proof routes, branch certificates, and simulation diagnostics.
- Do not ask for citations unless Op explicitly turns this into source work.

## Output Format

1. Executive assessment
2. Best next theorem target
3. Object and assumption review
4. Domain, chart, boundary, and invariant review
5. Theorem-ready pieces
6. Hidden assumptions and red flags
7. Proposed theorem
8. Proof strategy
9. Capture recommendation
10. Final recommendation
