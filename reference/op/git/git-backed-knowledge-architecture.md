# Git-backed knowledge architecture

This guide owns the accepted knowledge-provenance policy. The September 14 operator decision below supersedes the former Option A/B adoption and coverage-before-retirement requirements. The [operating guide](git-github-operating-guide.md) continues to govern daily collaboration.

## Accepted decision — retire Option A and Option B enforcement, September 14, 2026

The operator ended the migration and authorized teardown of both Option B and the corresponding Option A source-pinning machinery: “It was a reasonable idea to keep track of idea provenance, but not at the cost of halting progress.” The reported loss of a month of progress and rejection of another estimated week are the operator's cost assessment, not a newly measured benchmark. The migration is cancelled, not completed. No further full-B coverage, transition approval, source-record refresh or migration acceptance is required before removing these mechanisms.

The operator's assessment is that the underlying idea is good: tracking the provenance of ideas and the relationships between reasoning, assumptions and evidence can help preserve valuable knowledge. We have not found an implementation that delivers those benefits without materially impeding progress. This decision records an implementation limitation, not a rejection of the idea or a conclusion that a suitable implementation is impossible. Any future reconsideration should be justified by demonstrated low maintenance cost and support for productive work; this observation does not restart the campaign.

Idea provenance remains useful: record sources, assumptions, derivations, significant decisions and the evidence supporting results in ordinary readable documents and Git history. Preserve existing historical scientific evidence and its recorded identities without rebinding it to current code. A historical record does not acquire a requirement to remain executable with current source. Ordinary source edits, test imports, local setup, builds and publication must not require approval of a source-hash graph or updates to predecessor/transition records.

Remove A/B current-source admission, blanket embedded expected-source hashes, graph-selection enforcement, migration-only gates and tests, and obsolete live maps/readers once their callers are removed. Replace callers with ordinary module imports and data loading; do not leave no-op admission facades, a permanent opt-out flag, or a replacement integrity framework. Stop refreshing migration maps as a consequence of teardown edits. The later operator clarification includes residual source/document pins in scientific utilities and tests, even when they predate the migration. Remove empty `None`/`undefined` pin tables and optional expected-source-hash branches as well; disabling their values is not removal. A stored scientific receipt must not require current code or explanatory documents to retain the receipt's recorded source bytes. Numerical comparisons and checks on actual consumed data remain useful.

The operator clarified that the abandoned infrastructure's historical records must also leave the repository's current tree. Delete migration maps, predecessor and transition records, transfer proofs, repair receipts, inventories, trial outputs, copied source archives and obsolete campaign reports; do not relocate them into another repository archive directory. Remove callers that depend on these migration-created copies, retaining only genuinely useful scientific test data in ordinary fixtures where a current behavioral check needs it. Original scientific results and source material are distinct from copies created to service A/B enforcement. Keep the concise decision and lesson here; temporary teardown checkpoints are recovery aids to remove at completion, not a permanent replacement archive. Normal Git history retains previously committed versions; this decision does not request rewriting Git history.

Retain mathematical and behavioral assertions, independently justified reference values, schema and protocol validation, generated-output freshness, execution resource controls, normal Git publication safeguards and package authenticity checks. A digest identifying an actual scientific artifact, a database migration, or a published package is not automatically Option A/B machinery. Remove the source-pinning dependency around a useful check without deleting the useful check. Teardown does not confer scientific acceptance or authorize new simulations.

Implementation follows the ordinary development workflow: change connected callers, preserve useful behavior, and run the affected checks. The former migration and coverage-transfer requirements are cancelled. Completion removes the abandoned mechanisms and records from the current tree; it does not establish new scientific results.
