# Testing by situation: September 14, 2026

This review inventories the live testing entrypoints and explains their purpose and execution cadence. The operator subsequently authorized reconciliation of the publication documentation and timed execution of the ordinary Node, slow Node, Python and C++ selections. Execution results are recorded below as they become available; this is not a claim that the repository passes. The checkout is undergoing the accepted Option A/B enforcement retirement; changes after this snapshot require rereading the linked entrypoints.

The principal distinction is between software behavior, publication integrity, and scientific evidence. A runtime test can show that a control updates the intended state. A publication check can show that files and references meet a declared contract. A scientific comparison can show agreement with an independently constructed reference within a stated domain. These conclusions are different, even when all three commands return success.

## Review findings

1. **Resolved documentation mismatch:** inspection of `selectedChecks` in `check-content-integrity.mjs` shows the local/github profiles select the same list, without the retired Python admissions. Under the operator's instruction to reconcile the gate and the accepted A/B retirement, [PR lifecycle step 4](../../../op/git/pr-lifecycle.md#4-run-the-exact-state-pr-gate) now states that actual coverage and distinguishes focused Python/C++ validation from publication requirements. `node --test tests/pr-branch-process-conformance.test.js` passed all six tests in 0.227 seconds of Node-reported duration. A subsequent change to the executable selection requires renewing this description.

2. **Measured default-sweep boundary:** the aggregate's `skipWhen` and `reporting` fields leave the broad sweep opt-in and non-blocking. The three current workflow YAML files contain no scheduled broad sweep, Python suite or CTest job. Thus a green default publication gate is not full regression acceptance. A new workflow, explicit run receipt or changed aggregate would alter this boundary.

3. **Measured discovery difference:** `npm test` invokes general Node discovery, while the sweep explicitly selects `tests/**/*.test.js` and `tests/**/*.test.mjs`. Python includes both prefix and suffix naming conventions. These entrypoints must not be reported as interchangeable full-suite runs. A future unified selection manifest could make the intended coverage explicit, but adding one requires a practical consumer rather than another maintenance artifact for its own sake.

4. **Measured repeated work, unmeasured cost:** both Content Integrity CI and the Pages composite run Content Integrity. The local receipt also prepares runtime assets before an aggregate that prepares them again, and foundational routing can invoke checks the aggregate repeats. These are visible repeated calls, not measured waste: independent clean-runner validation may be intentional, and preparation may be inexpensive when unchanged. Measure stage wall time before changing cadence.

5. **Measured evidence-check boundary:** the release and performance checker implementations read saved evidence and source identities. Their pass means accepted evidence remains applicable under the declared identity rules; it is not a newly observed browser session. Preserve this distinction in PR reports.

6. **Inferred improvement priority:** the gate description has been reconciled and all four selections have now run separately with explicit skip/failure accounting; the next priority is failure disposition after active retirement settles. This would reveal actual omissions and cost without automatically promoting every checker into every commit. The recommendation should be revised if the stable gate or current run evidence already supplies equivalent coverage.

## Recommended operating pattern

For ordinary edits, run affected behavior tests and the relevant content or interface checks. For solver changes, add rebuilt CTest, independent oracle comparisons and appropriate sanitizer or refinement controls. For publication, run the declared candidate gate and the required remote build checks. Run broad and slow regressions deliberately, recording skipped and input-blocked cases; choose any recurring cadence only after measuring the stabilized suites. Run expensive scientific campaigns and export acceptance only for their owning situations.

The next decision is which tests must protect every publication, which should follow affected paths, and which need deliberate periodic or scientific execution.
