## Corrections and mathematical meaning

The scalar definition uses the geometric quantities and selected branch sign. Its gradient proof uses the root derivative. Accordingly, the candidate removes scalar → root-derivative as a prerequisite and supplies proof → root-derivative. It also removes scientific-check → measured-prose: the existing test never reads Markdown. The new candidate-only `prose-check` reads one uniquely identified displayed maximum and compares it with the corresponding executed output.

The proof follows the source reasoning: differentiating the causal constraint at fixed reception time and retained history gives the receiver derivative of separation. Constant coupling and constant branch sign allow differentiating the scalar without extra coefficient terms. The sign converts the signed transmitter denominator into its absolute value. Identifying this gradient with acceleration requires the independently declared canonical acceleration row. These premises are represented separately; the graph's traversal does not prove them.

Continuity and a nonzero transmitter factor support constant sign on a connected chart. The sign object's source binding includes that continuity argument. Disconnected components can have different signs while retaining the local identity componentwise. A changed sign sentence is therefore a review signal, not an automated theorem refutation. The [source-based review](option-b-dependency-map-review.md#what-the-mathematical-proof-actually-needs) contains the explicit differentiation and this boundary.

`dependsOn` carries an explicit role: mathematical prerequisite, domain restriction, proof support, implementation input, comparison requirement, or reporting provenance. `verifies` names a bounded numerical target; it is a candidate schema addition distinguishing a check target from a premise. `checks` names actual check coverage. `usesInput` and `generatedBy` describe the new observed execution. These predicates are interpreted only by this bounded candidate reader, not an adopted production schema or a claim of formal provenance-standard compliance.

For impact reporting, the reader derives a combined view of dependencies, verification targets, and execution provenance. An “affected” object needs review; it is not declared mathematically false, nor does a previously executed run change retroactively. A run in the affected set means its relevance to the changed candidate needs reassessment. Check selection retains old and new coverage edges. Any changed source file also selects both scope checks conservatively, including bytes outside selectors. Thus sparse selected objects cannot silently hide an unclassified source edit.

## Independence, provenance, and remaining limits

The scientific subject and independent reference bytes are unchanged. C solves scalar-side roots with its own Newton routine and numerical stencils; R supplies an unchanged bracketed-root record. Both use the same declared canonical model and matching circular geometry. That common model is a premise, not independently established by their numerical agreement. The new `reference-inputs` object binds R's circular history, direction, root, bracket, wake speed, and coupling. The comparison-requirement relationship makes the required correspondence explicit; the candidate reader does not algebraically verify every parameter match.

Numerical coverage remains the existing positive-transmitter-factor circular control, central receiver gradient stencils, analytic chart bounds and sampled checks. It does not cover negative-factor charts, arbitrary retained histories, every point in the receiver ball, singular continuation, global scalar existence, action/conservation closure or EOM solver acceptance. The symbolic theorem has its own declared hypotheses and proof; numerical coverage must not replace them.

The `proof` selector excludes the following measurement/action discussion. `theorem-claim` and `measured-prose` use separate literals; source justifications can still cover a broader paragraph for context. That deliberate overlap can conservatively flag the theorem record when the measured paragraph changes; it does not merge their claim grades. Coupling and constant-sign reasoning are explicit prerequisites. The canonical acceleration law is a retained boundary premise; this bounded map does not recursively model its whole theoretical derivation.

The new output has a `generatedBy` edge to the actual isolated run and binds its exact emitted bytes. Receipts identify commands, working directory, exit status, source hashes, stdout/stderr hashes and observed environment. Prose-comparison receipts additionally bind the checker, case prose, case output and comparison result. These are locally observed records, not authenticated operator approval or a trusted production receipt consumer. The original historical measured-prose statement has no fabricated `generatedBy` edge to this new run: its original producing activity remains unauthenticated.

No graph algorithm can identify an omitted relationship absent from both old and new maps. The candidate therefore addresses the reviewed omissions without claiming exhaustive completeness. Its validator is bounded: it checks bindings, endpoint versions, duplicate identities/relationships and selected predicate endpoint types, but does not implement the complete proposed production schema, strict rejection of every extra field, general trust policy, hostile input validation, concurrency control or cross-scope historical interpretation.
