## Required current-build context for full phase acceptance

The remaining obstacle is an executable contract, not a missing permission to run an otherwise compatible pilot. `prepareSubfieldCircularPhaseLedgerContext` in the unchanged `SubfieldCircularRootLedgerReducer.mjs` calls its private `verifyBuild`. That function hard-pins the old adapter (`42dc7e…`) and old CMake generation (`e4b3a8…`), in addition to unchanged History and Interval API dependencies. The new concrete build therefore cannot enter that context. The existing pilot and rung wrappers also select the original build receipt `be6f2e…`; the rung's outer-supervisor pin remains old. None of those original records was overwritten or relabeled.

A future independently reviewed current-build context interface needs the following explicit inputs and obligations:

1. **Current build identity.** Accept the original bytes and expected digest of the current build receipt, plus its separately recorded review. Check every declared source, header, tool, library, executable, and build-stage log against its recorded identity; require before/after equality, successful closed stages, the accepted adapter schema-only generation, reviewed current CMake, and unchanged History/Interval/ExactPair dependencies. Keep the existing platform-library boundary explicit.
2. **Current mathematical inputs.** Accept the exact manifest and independent conformance bytes and hashes, rung and phase, and original seven reference bindings. Preserve source membership/order, the complete segment grid, numeric carrier bits, history fingerprints, independent inflated-speed bounds, and proof identity checks currently enforced by the reducer. Build review cannot replace any of these predicates.
3. **Unchanged row predicates.** Delegate the existing ordered-pair, root/domain, cited-segment coverage, endpoint-self, cache-cell, precision, and authority predicates without changing the numerical reference in the adapter repair. A production context must retain the current stop-after-first-invalid-row behavior, exact row census, source rechecks, and original-row hashes. The exported abstract `inspectSubfieldCircularRowForTests` explicitly lacks source/file authority and cannot be promoted to an accepted phase.
4. **Current process and resource plan.** Bind the resulting context API, current phase-process helper, pilot/rung/dispatcher, and outer supervisor. Require fresh closed phase records and a complete accepted 32-phase, 2,448-row pilot before using the existing ladder prerequisites. Its resource plan must account for all sixteen candidates, preserve the declared memory/disk limits, and carry the reviewed per-cohort wall limit. The zero-row handshake supplies neither that pilot census nor candidate cost estimates.

This interface is a proposal for the next independent contract review, not an accepted replacement API. The existing private build verifier must not be monkeypatched, its expected source map must not be forged, and a test-only context must not be used as phase authority. The current repair intentionally leaves the independent reducer byte-identical. Full pilot/ledger acceptance remains open until that reviewed interface and its negative controls exist; successful current adapter and handshake checks do not close it.
