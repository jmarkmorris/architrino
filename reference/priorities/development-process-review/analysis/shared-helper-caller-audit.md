## What the bindings mean

A current execution binding selects the actual program about to execute. An old receipt's source binding identifies the program that produced that receipt. The same pathname can occur in both roles, but replacing the hash in one does not authorize replacement in the other. A third role appears here: an independent scientific verifier may require a particular operational generation as part of the precise launch contract it accepts. Such a requirement is executable validation logic, even when the selected program implements only process supervision.

This distinction prevents a mechanical fixed-point hash replacement from being an adequate repair. In particular, the refined-acceleration verifier is also imported by the working parent and variable-cell paths as a current transport library. Altering its historical requirements to accommodate new launches would change the subject of those working readers. The existing archive selection supports preserved old bytes, but does not authorize an archive to supply executable helper code for a new run.

## Recommended forward contract and order

The recommended direction is to preserve the existing scientific capabilities while giving current execution its own explicit operational generation. Do not launch old archived supervision code to satisfy a pin, silently broaden historical readers, or remove a test merely because it exposes this conflict. The alternative of retiring old launch profiles is an architecture decision: the basename census finds live code/test consumers, and historical use alone does not establish that an executable capability is unnecessary.

1. **✓ Done — Current operational profiles implemented.** Historical requirement: Specify a current operational profile for the one-cell root-cover and cached-root-cover paths, where the independent Python comparison contract already separates mathematical source/runtime bindings from the launcher's operational census. Preserve the mathematical subject and comparison bytes. Bind the selected current helper and actual host observation executable in a newly reviewed machine plan. Verify host-output parsing and resource-stop semantics before treating that executable selection as admissible. Keep existing scientific input bounds, one-cell scope, independent comparison, deadlines, and rejection rules.
2. **✓ Done — Bounded profile controls; full scientific execution remains separate.** Historical requirement: Validate the complete profile, including current source composition and externally observed bounded process controls. Existing source-copy tests need a stated purpose: historical source derivation should read preserved source bytes; current behavior tests should exercise the supported current composition. Neither proves the other. The full-run profile follows only after its separate acceptance requirements are addressed; a synthetic one-cell test cannot authorize full scientific execution.
3. **✓ Done — Current acceleration and prescribed-response transport.** Historical requirement: Migrate acceleration and prescribed response after resolving the exact changed declaration/configuration/fixture roles. Authenticate old inputs as old inputs or obtain a reviewed current scientific input selection. A current path with a new hash does not inherit an old source's scientific authority.
4. **◐ Partial — Emission complete; refined execution blocked by exact originals.** Historical requirement: Specify a versioned new-run operational interface for emission/refined acceleration. Preserve the refined verifier's historical transport API and its old predicates. Review the independent verifier's new interface separately from the subject migration, so their agreement cannot be used as evidence for a simultaneously changed mathematical rule. The current parent/adapter transport dependency must remain explicit throughout.
5. **◐ Partial — F5 complete; circular ladder contract in progress.** Historical requirement: Review the F5 build and circular ladder against their existing build/pilot and resource-plan requirements. Keep their capabilities unless retirement is explicitly chosen after consumer review; do not infer retirement from a dated filename.

These original migration requirements now have the current operational statuses shown above. The operator selected restoration through supported current profiles. The remaining executable work is the circular ladder contract and the original-input-dependent refined path; the [work queue](../work-queue.md) retains their current acceptance conditions. No completed operational profile supplies broader scientific acceptance.

## Validation, limits, and falsifiers

Before target inspection, the inventory instrument passed SHA-256 `abc`, literal line/token extraction, and matching/differing/missing-file cases. Each existing entry's binding API then passed a literal three-byte positive case and a wrong-hash negative case before checking the actual helper selections. The inventory records rejection reasons. The first inventory attempt failed because this audit named a nonexistent diagnostic file; the corrected path was obtained from the coordinator's live `PINS.diagnostics`, all controls were rerun, and only the successful inventory is treated as a result.

The existing cached-root test was selected by exact test name, with no scientific data load or process fixture. Its original failure is retained; the later current-profile migration and controls resolve the supported operational selection, as linked above. This audit ran no broad test sweep, mathematical computation, full pilot, or historical replay. It changed no operational implementation, verifier, test assertion, scientific artifact, or archive bytes after the initial requested publication. It does not establish repo-wide binding coverage: the token census covers tracked `scripts/` and `tests/`, and the reference census is a literal basename search of tracked repository files, not a dynamic call graph.

The findings are overturned if the recorded source bytes are wrong, an inspected current binding API accepts the recorded mismatching helper, or the apparent current selection is demonstrated to be an exclusively historical, nonexecuting role. Support or retirement decisions must additionally be checked against the recorded consumer references. A full successful new launch would need the declared independent scientific and operational acceptance evidence; passing this inventory is not that evidence.
