# Option A validation: historical root-cause analysis

This investigation distinguishes the creation of an integrity check, a later valid alarm, and damage caused while responding to that alarm. A **binding** associates an expected identity with particular source bytes; a **pin** stores that identity as a literal. A **receipt** records a particular execution or acceptance decision. SHA-256 detects a difference in bytes; it does not determine whether an equation is correct, whether an edit is justified, or whether a historical result remains applicable.

**Completed bounded investigation, September 12–13, 2026.** The answer is that substantial components were vetted, but complete vetting of the published composition is not established, and two concrete bindings already fail in the first retained snapshot. Later failures combine ordinary source changes, incomplete dependency propagation, historical/current identity confusion, a supervisor lifecycle defect, deficient validation coverage and environment isolation, and inadequately supported diagnosis. No single actor or hash defect explains the whole campaign. The [coverage record and evidence index](../evidence/option-a-validation-rca/README.md) distinguish original records, new measurements, partial source review and unavailable evidence. Unresolved individual transitions are stated below; this is not a complete scientific revalidation or a claim that every historical event has been explained.

## Principal findings

The original integration gap is directly measurable. In `0fb575921`, the full-resource-plan and member-predeclaration expectations disagree with the documents at their current paths. Both expected identities match independently retrieved Git blobs exactly. These are real older generations, not invented or shortened hashes. The original cached-full test explicitly checks the first document at its current path, so that committed composition cannot pass that assertion. A retained successful run using the older bytes remains possible and is consistent with the readiness record. What is missing is successful validation of the final committed composition, not all prior testing.

The hypothesis that Claude exposed pre-existing failures is supported for specific cases. It is not supported as a blanket description of every failure subsequently counted in recovery. The enclosure-contract test matched the committed document at its August 27 introduction, became stale after the September 1 rename, and still expected the original bytes when the later review exposed it. Its alarm was valid. This example establishes a maintenance and selection failure after introduction, not an invalid initial expectation or damaged mathematics.

Conversely, the four test-source bindings grouped under Agent 2's F06 heading were valid in the introduced committed state and on September 1. The September 6 import-path repair changed their subjects without updating those consumers. The heading “stale since `0fb575921`” therefore needs narrowing. The report's detailed discussion of `d52665793` is consistent with the measured transition. The original report is preserved.

The most consequential repair error is the substitution of current executable identities into a historical predecessor contract. In `prepare-f6c-parent-emission-refinement.py`, `ORIGINAL.fullEntry` matched the retained full-admission receipt at introduction. Commit `baa3e7323` first replaced it with the current entry's hash; successive repairs kept advancing it. This can make a present-file check agree while invalidating the older receipt's meaning. The exact transition predates the seven-commit consequential audit and Agent 2's reported starting HEAD. The Git transition identifies changed bytes, not the human or agent who authored them.

A separate pin in the same commit identifies an intermediate preparation state rather than either its parent or committed child. Reconstructing the parent with only the helper substitution reproduces that expected hash exactly. Earlier commit `d52665793` had already made this preparation pin stale through an import/schema change. Thus there are two observable defects in sequence: incomplete propagation, followed by capture of an intermediate state. Concurrent publication is a plausible contributor, but these bytes do not establish who read or wrote them at what uncommitted instant.

The September 12 dispatch incident is independently localized to coordinator-authored content before transmission. The measured source hash is correct; the literal in the assignment is missing its last character. Constructed, outgoing, and incoming prompts are identical across the affected dispatch and four siblings. This rejects transport alteration as the explanation at the retained local boundaries. It does not prove live transport behavior at arbitrary sizes, and this later incident cannot cause the September 6 failures. An older instance of that exact one-character transcription mechanism has not been established.

## What Option A actually was

“Option A” is a retrospective architectural label. In the inspected Git history, `git log --reverse -S'## A. Current file checks'` on the process campaign first returns `6a637f574c6455db8567f08a2d4e93b1cf9f189a`, September 8 at 01:18:15 EDT; its actual added document contains the A/B comparison after the September 6–7 recovery. `ab1d81d8e` moves that material into the architecture owner later September 8. This establishes the label in these retained documents, not the first spoken use or an August design decision to build one unified A pipeline.

The August and early September code instead contains several cooperating mechanisms with different obligations:

This reconstruction comes from the named historical code at `0fb575921` and `897fe1aa7`, the September 2 watchdog transition, and the retained contracts. Exact expectation-authoring commands and all original author deliberations are not recovered. Matching an expected literal to an independent old blob establishes its referent; it does not identify who measured or copied it.

Whole-file identity has a deliberate broad trigger: punctuation, line endings, equations and executable changes all alter the selected bytes. The design problem was managing the resulting obligation, not SHA-256 mistakenly equating those changes with mathematical damage. A dependency chain also makes editing a pin-holder change that holder's identity, which can invalidate its own consumers. A correct inventory and final-generation check are therefore required wherever exact transitive identity is an actual obligation.

## Process failures and validation exposure

### A missed normal-completion case

The [first process investigation](first-process-investigation.md) retains a separately constructed minimal workload: write a marker, then return. On the Mac it rejects after about five seconds; adding explicit process exit succeeds in 0.269 seconds. Releasing watchdog references in memory instead produces `SIGKILL`, which correctly rejects. This is stronger evidence than a general inference from a hanging scientific test, and contradicts “missing Python is the necessary cause.” It does not identify the OS signal sender or prove that every reported stall has one cause.

The operations work log records finding those exact fixture settings in the actual repository and repairing the route. `git show f285eb4f4` independently confirms the coordinated variable-sanitization change.
