### Owned-supervisor recurrence repair, 2026-09-07

The interrupted publication gate exposed a separate defect in the generic supervisor's reporting boundary. Inspection of `classifyLease` showed that loss of the group leader alone produced `stale_closed`; the implementation did not check for surviving descendants or a surviving sidecar. The foreground waiter also consulted only the durable terminal status, so a lost sidecar could leave it waiting until the original workload deadline. Neither observation establishes why the sidecar disappeared in the original incident.

The current implementation checks group existence and sidecar absence before classifying an abandoned run as closed. Missing ownership identities, a surviving group, or a surviving sidecar retain the identity-uncertain classification and prevent closeout or automatic signalling. Foreground execution checks the recorded sidecar identity every second and reports lost supervision if the sidecar disappears without a terminal result; a second lease read protects the ordinary final-write race. An acknowledged stop can now return observed closure when both processes disappear before a terminal write. That result remains `stale_closed`, with no fabricated exit code or success; explicit reconciliation records `reconciled_closed`.
