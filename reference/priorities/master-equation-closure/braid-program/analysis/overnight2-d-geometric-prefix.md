# Preserving complete steps from a closed geometry-comparison run

The [geometric-prefix adapter](overnight2-d-geometric-prefix.py) extends the previously reviewed [admission-prefix selection](overnight2-d-admission-prefix-independent-review.md) to exactly two additional producer entry paths: the [geometric composition](overnight2-d-geometric-admission.py) and [screened composition](overnight2-d-screened-geometric-admission.py). The original extractor remains frozen and continues to reject those paths. The [independent component review](overnight2-d-screened-and-prefix-independent-review.md) accepts the repaired selector. It has not extracted a scientific target.

The new recognizer first requires an exact supported entry. It then reuses the unchanged original argument parser through a private copy of the command array, replacing only the entry token for parser compatibility. All scientific arguments, the terminal/closed requirements and canonical-option checks remain unchanged. The actual lease is never modified, and output does not claim that the old producer executed. Both new producer CLIs use the same argument defaults; an explicit output option is required by the underlying recognizer, so their different default output names cannot be confused.

The original target authenticates the supported command and terminal closed status before reading a partial. A wrapper captures the executed entry from that exact authentication call; a second wrapper validates required bindings on the exact header returned by the original extraction from the consumed partial bytes. That header must bind the executed new entry, original geometric composition, midpoint helper and original admission core. There is no preliminary partial read. The existing target then checks lease identity and checkout, exact parsed request/header equality, complete chronological eight-member steps, exact previous records, mesh endpoints, all dependency hashes, selected whole-prefix limits, unchanged source/lease bytes and outward final position conversion. The new extractor adds its own source identity to the inherited dependency merge; the original extractor and residual-prefix helper remain bound as well. All original partial bytes are retained, including excluded later records or fragments.

This is evidence selection, not scientific validation. A closed same-name run alone does not establish that it created a partial; independent launch, output-refusal and flushed progress evidence remain required. A selected prefix retains null isolated runtime/resource cost rather than inventing a cost for part of a run. Its mathematical comparison, source coverage, trial closure, dependencies and creator association still require independent adjudication before acceptance.

Known controls passed before target use: the inherited exact whole-prefix and malformed-input checks; both exact new entries; live-run, unrecognized-entry, abbreviated-option and duplicate-option rejection; and binding of the new extractor itself. A misidentified producer, changed or incomplete history, altered dependency, noncanonical request, inward conversion or unsupported creator claim would invalidate an extracted result. No ongoing partial is used as accepted evidence, and this adapter by itself admits no additional trajectory time.

Independent review found a required repair before any scientific use: checking required bindings on a preliminary header did not protect a later reread by the underlying target. The initial source and note are preserved locally. The revised wrapper checks the actual consumed extraction header, and the unchanged closing checks protect those same bytes and lease. Known controls pass, and separate adversarial verification accepts the repair: replacing the input between reads or omitting the executed binding from the stable consumed header is rejected without output.
