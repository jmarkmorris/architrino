## Selection and fallback

The adapter first constructs the midpoint geometry. It then attempts the original polynomial geometry, treating `ValueError` or `AssertionError` as an unavailable polynomial enclosure. If both are available, it selects the smaller root-shift upper endpoint, with ties choosing polynomial. It returns a new dictionary carrying the chosen complete set of fields and its method label; it does not mix the root shift from one construction with the delay center or vector box of the other.

This last point is necessary because the two proposals and candidate vector boxes may differ. A smaller root-shift radius is a valid selection heuristic, not a proof that the entire selected source interval or vector enclosure is contained in the other. The selection remains sound because both independently establish the complete consumer contract. It is not an interval intersection or a minimization theorem. A later matrix or history gate may still fail even though the other candidate would have been useful.

Fallback is deliberately asymmetric. The midpoint construction is mandatory and runs before the polynomial attempt; its failure propagates, even if a polynomial construction might succeed. Only the stated polynomial exceptions select the already valid midpoint alternative. Other exception classes propagate. This can reduce availability but does not weaken a certificate. The adapter must not be described as trying every valid alternative after every failure.

The selected dictionary retains the encoded candidate delay interval, complete candidate source interval, candidate-vector box, certified reference shift, speed bound and member indices. The reviewed unchanged source/matrix consumers add the translation shift and vector enlargement according to those meanings. No velocity perturbation is inserted into the geometric root equation. The inherited complete source-piece, acceleration-trace, separation and shifted-denominator checks remain in place.
