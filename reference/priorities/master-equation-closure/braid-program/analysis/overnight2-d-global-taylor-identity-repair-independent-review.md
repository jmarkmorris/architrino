# Complete-bound Taylor consumed-identity repair: independent verification

## Disposition

**Repair accepted as a conditional implementation component.** The actual input-header and final-receipt serialization paths now bind the activated domain values to the original snapshot's byte identity. The previously reproduced replacement between activation and dependency capture is rejected before a scientific cell or a usable header is written. This closes the finding in the [preserved initial review](overnight2-d-global-taylor-independent-review.md). It does not accept an unrun original-preparation pilot, establish a speedup, or extend actual history.

The same retained Moore lens, Specialist charter and scoped-write boundaries apply. No source, oracle, prior review or scientific input was edited, and no active partial or scientific target was replayed.

## Exact change and argument

Direct diff against the preserved pre-repair source shows the change is confined to importing hashlib, retaining the domain path/raw-byte SHA in context, adding capture checks and their controls, clearing the added context fields, and replacing only the private imported core's json binding with a loads/dumps proxy. The scalar Taylor bound, source selection, matrix path, inherited core source and prefix adapter are unchanged.

The wrapper now reads the snapshot bytes once, computes their SHA-256 and parses that same byte sequence. The existing consumed-object comparison and inherited dependency verifier still precede activation. When the core serializes its actual kind=inputs header or its full final receipt, the guard requires active context and exactly one dependency for the snapshotted domain path, with its snapshotted SHA. It then delegates the original payload and arguments to the untouched standard-library json.dumps.

For a replacement after consumption but before dependency capture, the core would record the replacement hash; the guard rejects it against the consumed snapshot before serialization. A replacement after capture remains subject to the core's unchanged closing dependency-byte check. A missing or duplicate domain identity also rejects. The actual final receipt includes records, arguments, dependencies and cells, so it satisfies the guard's final-payload predicate; the shorter terminal stdout summary intentionally does not substitute for this guarded final file.

This is a guarantee about the declared frozen in-process call sequence, not arbitrary monkeypatching by an external adversary or unauthenticated creator association. Later application acceptance must still verify the exact domain, reference, producer and receipt identities.

## Independent verification

The private script .tmp/overnight2-d-review-global-taylor-repair/independent-controls.py first runs all inherited known controls. It then separately exercises the installed core json proxy, rather than only calling check_capture:

- Header and final payloads with the exact single dependency serialize byte-for-byte identically to standard json.dumps, including indent and sort arguments; the input objects remain unchanged.
- Missing, duplicate and incorrect domain identities reject for both payload classes.
- A correct header rejects when activation has not succeeded.
- Ordinary control payloads serialize normally; the standard-library json.loads and json.dumps function identities are unchanged.
- The actual frozen core main resolves its json global to the private proxy.

A second independent synthetic test executes the unchanged core main end-to-end in a private synthetic repository. Only scientific calculations and their data sources are replaced by analytically declared control values; the original file-load, bind, dependency-capture, header/row/final write and wrapper-cleanup paths execute. No original trajectory is run.

The normal case produces the exact expected header and final serialization with the consumed domain hash. The original defect is then reproduced as a private domain replacement from eight acceleration bounds equal to 5 to bounds equal to 6 after the first bind but before identity capture. The repaired actual header path raises the intended identity error, the scientific cell stub is never called, the opened partial contains zero bytes, and no final output exists. Finally, injecting a wrong domain identity into the actual final payload raises before final-file output. Context is cleared after every success and failure.

An empty partial left after header rejection is fail-closed evidence: it contains no usable header or complete admission cell and cannot constitute an extracted certificate. These controls do not assert that failure leaves no filesystem trace.
