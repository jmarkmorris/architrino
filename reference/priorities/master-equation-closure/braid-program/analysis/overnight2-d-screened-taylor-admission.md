# A speed-width screen for the Taylor geometry

The [first Taylor composition](overnight2-d-taylor-admission.py) selected Taylor geometry on 30 of the 56 channels in its original cell-423 pilot and fell back on the other 26. It completed in 33.740381833165884 target seconds, compared with 37.53396458411589 for the earlier geometric composition on the same cell, incoming423 history and six residual inputs. The pilot reported a closed first trial but awaits independent output adjudication. These are measured single-cell costs, not a future runtime guarantee.

The proposed [screened Taylor composition](overnight2-d-screened-taylor-admission.py) uses the already reviewed speed-width threshold $L(b-a)/(1-L)$ from the [screened geometry argument](overnight2-d-screened-geometric-admission.md), applied to a complete valid Taylor enclosure. It replaces the first Taylor pilot's narrower cell-width/100 selection heuristic. The scalar comparison, physical model, error allowance and accepted past do not change. A larger valid geometry enclosure can increase the later matrix/error bounds, so every downstream gate still determines whether the choice is useful.

The new composition attempts the reviewed Taylor enclosure first. If its reference shift upper bound is at most the conservative speed-width threshold, it returns that entire contract with the Taylor method label. Otherwise, or on the same caught unavailable-enclosure exceptions, it delegates to the frozen screened polynomial/midpoint construction. It does not take the radius from one candidate and the vector or delay from another. No minimality, interval containment between methods or guaranteed cost reduction is asserted.

All original Taylor metadata, complete core checks and source bindings remain; the new selector appends its own executed source identity. Inherited controls exercise the new geometry dispatch. An independent exact threshold example with speed1/2 and width1 checks selection on either side of threshold1. These controls passed before target use. The independent component review accepts this integration; the same-cell pilot completed and awaits independent output adjudication. Only the separately reviewed Taylor prefix adapter recognizes these two Taylor producers.

A selected invalid or mixed contract, lost dependency, changed prior record, omitted source/jump term or bypassed strict-trial gate would invalidate the composition. A measured same-cell result is required for any performance statement. No new actual trajectory time follows from this proposed selection rule.

The separate [Taylor prefix selector](overnight2-d-taylor-prefix.py) composes the repaired consumed-header extractor without editing it. It recognizes exactly the original and screened Taylor entry paths, requires the Taylor helper, original Taylor composition and inherited screened composition on the actual consumed header, and retains the earlier checks for the authenticated executed entry and common geometry/core sources. It appends its own identity to the complete extraction dependencies. All command, closed-run, exact-prefix, source-byte, lease-byte and exclusive-output checks remain in the original consumer. Writer association and full mathematical adjudication remain independent obligations. Known exact-entry, missing-required-source and identity controls passed before any scientific extraction; the [independent component review](overnight2-d-screened-taylor-and-prefix-independent-review.md) accepts this extension together with the selection composition.
