## Required repairs and their exact scope

1. **Reference arguments are not associated with the header.** `closed_run` checks the script, mode, output name, first/count and ordered receivers, but does not parse the producer's `--tag` or `--domain`. A synthetic closed failed lease with `--tag other-reference` passes the current function; a separate partial header containing `mesh-reference-t67` is then accepted by the target. Parse the producer's effective reference/domain arguments, including their defaults, and match them to the header and required bound reference/domain inputs. The reviewed producer source itself should be explicitly required in the header dependency inventory when its per-row contract is relied upon. A list of whatever dependencies happen to be present is not by itself a check of that contract's complete binding.

2. **A matching output name does not prove that this run created the partial.** The producer refuses a pre-existing partial or final output before opening its new partial. Consequently an earlier retained partial and a later closed failed launch with the same output name, selection and unchanged inputs can satisfy every current extractor check while the output attributes the earlier file to the later run. Stable bytes, same checkout and terminal process-group closure do not distinguish this case. Establish creation association from independently retained launch/file/run evidence, or explicitly withhold source-run attribution until such evidence is adjudicated. A suitable repair must reject the same-tag retry counterexample. It need not expose lease control credentials; sanitized operational evidence can retain the needed identity, arguments and creation association. This defect concerns provenance and honest resource attribution, even if the older rows happen to remain mathematically valid.

3. **Duplicate JSON keys are silently collapsed.** Standard `json.loads` accepts a complete row containing `"cell":99,"cell":11` and returns cell 11. The synthetic control confirms that this row is selected as though the earlier value were absent. Genuine `json.dumps` producer dictionaries have unique keys, so this does not show corruption of existing producer output. It does defeat the broad malformed-input and no-alteration contract for the parser. Reject duplicate keys at every object level, or explicitly narrow the contract to independently authenticated producer JSON and enforce that premise before selection. Strict rejection is the direct repair.

4. **Endpoint equality needs an explicit index and pair guard.** The comparison `row['interval']==list(times[k:k+2])` accepts `[]` when an out-of-range cell gives an empty slice. Require $0\le k<\operatorname{len}(T)-1$, exactly two finite increasing endpoints, and equality to that valid cell. A genuine validated producer cannot emit the offending row; nevertheless the current advertised endpoint check should reject it rather than defer it to scientific review.

These findings were sent to the parent before any source edit or scientific extraction. They do not justify changing the frozen residual producer or admission consumer. They also do not establish that the current active run has any of these defects; no live target was inspected.

## Selection and finite-input behavior

The `prefix` function requires exact integer first/count parameters and a newline-terminated `kind=inputs` header. For every complete line it computes the expected cell as first plus the number of preceding rows divided by eight, and the expected receiver as that row count modulo eight. Exact integer cell and receiver types reject Boolean and floating indices. This induction proves that each group of eight selected rows contains exactly receivers 0 through 7 of one consecutive cell, without reordering. Extra complete rows beyond the declared run selection are rejected.

The selected count is a nonempty prefix of the available complete groups. Rows from an unfinished final cell are excluded and counted together with any deliberately unselected complete rows. A final non-newline fragment is not parsed; even a syntactically valid complete JSON object without its newline is conservatively excluded. Complete malformed JSON, including an invalid line after an otherwise selectable prefix, aborts the current extractor. Thus it does not salvage a prefix past an arbitrary corrupt complete line. The note's claim that an independently isolated later failure need not refute earlier rows is mathematically sound, but does not mean this parser ignores malformed later complete lines.

Recursive finite-value checks reject nonfinite floats in lists and dictionaries, including the standard parser's `NaN`, `Infinity` and overflowing exponent forms. Wrong row container types can raise a generic exception rather than the intended `ValueError`; this still prevents output. Genuine producer integers are retained exactly and finite binary64 numbers round-trip through Python JSON without numeric change. Whitespace and lexical spellings are regenerated, so this is object-value preservation, not byte-for-byte row copying; the original raw partial remains the byte evidence. Duplicate-key handling requires the repair above.

## Producer contract and admission boundary

Read-through of frozen `overnight2-d-adaptive-residual.py`, SHA-256 `3676397915b444f2d6dd317610a50349b281723c2f340dfcd2cf576acb116e1b`, confirms the relevant sequence. `receiver_row` computes the entire ordered reception partition, all channel bounds and its outward integral before returning its dictionary. The main loop visits selected cells and receivers in order, writes one JSON row plus newline only after that return, then flushes. Earlier rows are not numerically revised by later work. A timeout or other exception during the next member can therefore leave completed previous rows and a missing or truncated final record. A resource-cap exception after a flushed row likewise does not erase that row. Flush establishes the producer's ordering contract; it is not a promise of crash durability, so extraction still needs a readable stable complete record.

The producer's normal final path rechecks input hashes before writing the aggregate JSON. A stopped or failed partial may not have reached that check. The extractor therefore correctly rechecks each retained header dependency against current bytes and again at closure, and binds the complete original partial plus extractor source in the output. This protects present byte identity. As with the existing successful-run contract, it does not prove that a file was never transiently modified and restored during computation; unchanged scientific dependencies throughout the owned run remain a provenance premise. Scientific adjudication must assess any actual failure cause rather than treating all closed failures as benign deadlines.

Read-through of frozen `overnight2-d-delayed-admission.py`, SHA-256 `d0ecd08abb5e714a3c8611e10ffec79d7cb642401f68a0ae582f2d400e7ada7f`, confirms that `bind` rechecks declared hashes and `residual_inventory` requires complete requested cell/member coverage, rejects duplicates, verifies encoded cell endpoints, recomputes each reception-partition integral and requires all seven distinct source partners. It can consume a prefix receipt once independently accepted. These consumer checks do not prove every signed acceleration enclosure, denominator/bridge bound, source trace, front bracket or arithmetic assumption. The full mathematical row audit remains required, with exact selected-row correspondence to the retained partial and all source/dependency identities. Extraction alone is never permission to promote rows into a trajectory certificate.
