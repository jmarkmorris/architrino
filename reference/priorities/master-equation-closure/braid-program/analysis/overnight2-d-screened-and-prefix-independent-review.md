## Screening derivation and implementation

For $0\le L<1$ and $b>a$, the exact threshold is $q=L(b-a)/(1-L)$. A midpoint $m\in[a,b]$ has $h=\max(m-a,b-m)\ge(b-a)/2$. Since the point-gap bound is nonnegative, the midpoint displacement expression obeys $(\epsilon+2Lh)/(1-L)\ge q$. The screen uses an interval lower endpoint of $q$, clamped below by zero. Both zero and that lower endpoint are lower bounds on the nonnegative exact $q$, so the clamp is conservative.

More fundamentally, choosing an already valid polynomial enclosure is sound even without comparison to the alternative. The code returns the entire polynomial dictionary plus its method tag; it does not mix its vector, source or delay with the midpoint construction. Failure of the polynomial construction through its documented domain exceptions leads to the midpoint alternative and accepted chooser. When a valid polynomial passes the screen, the midpoint is not evaluated, so an unavailable midpoint need not abort that path. Where midpoint evaluation is required, its failure propagates.

Independent controls used the exact threshold $q=1/2$ from $L=1/4$ and width $3/2$, with shifts $1/4$ and $3/4$, plus $L=0$. Stubbed calls exercised the actual geometry dispatcher: polynomial-only selection, polynomial-then-midpoint selection, both caught exception paths, skipped midpoint failure and propagated required midpoint failure. Returned candidate fields retain their object identities and the original dictionary is not mutated. These controls test known call ordering and whole-contract selection; they are not floating target parity.

Runtime binding inspection verifies that the screened source is appended through the older adapter, retaining both the older geometric adapter and midpoint helper. The core `main`, `cell_step`, `resume_history`, `initial_bounds` and `residual_inventory` source bodies match a separately loaded frozen core. The actual module's cell step resolves the new geometry callable, its matrix callable remains the accepted adapter wrapper, and its main resolves the new binder. This is measured composition/preservation evidence, not a second independent scientific implementation.

The complete speed/reference premises remain caller obligations inherited from the core. The screen alone is not a public validator for malformed geometry dictionaries or invalid $L$. It does not change source-before-cell, refined containment, full source-piece and trace coverage, factor domains, signed matrix summation, residual/jump budgets, saved history or strict trial gates. It also does not guarantee the smallest complete matrix enclosure or exact selection parity at floating boundaries. No performance conclusion follows from this review.

## Required repair: check the consumed header

The frozen adapter reads a partial once to check required paths, then `base.target` reads it again. The inherited closing source-byte and dependency checks bind the second read. They do not establish equality with the first header on which the new adapter's required-path condition was tested.

The independent full synthetic counterexample supplied a first read with all required bindings and then a stable second partial whose header omitted the executed screened source. The original target accepted and emitted a selected receipt lacking that source dependency. This does not assert that any real retained partial was replaced. It demonstrates that the advertised fail-closed required-source guard does not cover the bytes actually consumed.

Required correction: validate the required sources on the exact header returned by the extraction path consumed by `base.target`, using the exact supported entry authenticated for that same invocation, or establish equality of the preliminary and consumed bytes before writing any output. The old closing byte/lease checks can then protect that same input. The old subjects must remain frozen; a repaired adapter needs a separately identified verification stage. The parent acknowledged this defect and proposed moving the check into a wrapper around `base.extract` with the executed entry captured by the actual `base.source_run` invocation.

Creator association remains a separate obligation even after this repair. A terminal same-name lease and a stable partial are not proof of the writer. A real application must still establish independent launch/progress/output-refusal evidence and complete mathematical prefix validity. Extraction never turns a failed enclosing run into successful whole-run science.
