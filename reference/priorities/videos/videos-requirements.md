# Videos Requirements

## Scope

The videos workstream must support AI-assisted media for:

- Architrino apps;
- Architrino theory explanation;
- web navigation tutorials;
- public videos;
- charts and visual summaries;
- markdown formulas or paragraphs used as video source material;
- still images;
- concept animations;
- narration;
- character appearances in video, image, and animation;
- and voices.

Generated media may use lifelike, illustrated, animated, or cosplay-style presentation. The default characters must be fictional unless the operator has explicit rights and consent for a real person's likeness or voice.

## Production Workflow Requirements

1. Each video or clip must begin from a reviewed script or outline.
2. AI may draft scripts, shot plans, prompts, captions, narration, charts, formulas, and source paragraphs, but operator review is required before public release.
3. Dry runs must be available for sections before committing to final media generation.
4. The workflow must support both one-shot short-form production and a longer repeatable pipeline.
5. A live-streaming mode may be explored, but it must not bypass script review, factual review, captioning, or archive retention.
6. Final media should retain source artifacts: script, prompts, character references, voice settings, generated assets, review notes, and exported files.

## Quality Control Requirements

Every released video asset must pass checks for:

- factual accuracy against the current repo source of truth;
- clean distinction between established theory, speculative explanation, and app/tutorial instruction;
- consistent fictional character appearance across scenes;
- voice quality, pacing, intelligibility, and pronunciation;
- captions or transcript availability;
- visual legibility on mobile and desktop displays;
- platform-specific framing and duration;
- no unlicensed imitation of real people;
- no unsupported claims that generated characters are real people;
- and traceability from final output back to the reviewed source material.

## Character Ensemble Requirements

The initial recurring ensemble should include four fictional STEAM-aligned characters: three explanatory leads and one skeptic. Any character may appear alone, with one other character, or with any subset of the ensemble.

`STEAM` means:

- Science;
- Technology;
- Engineering;
- Arts;
- Mathematics.

The ensemble should have:

- a sophisticated, articulate, highly educated, and well-spoken presentation register;
- appealing, high-quality voices;
- visually appealing lifelike and animated appearances;
- thin, fit, athletic builds that read as regular gym habits;
- well-fitted clothes that accentuate their bodies while staying sophisticated and camera-appropriate;
- stable character names, roles, voice notes, and visual references;
- enough variation to support dialogue, questions, demonstrations, and peer explanation;
- and character boundaries that prevent demographic or appearance traits from becoming stereotypes.

Initial appearance directions:

- an auburn-haired woman, optionally with Ukrainian design influence;
- a blonde woman;
- a light-skinned Black man;
- a blonde woman with an experimentalist skeptic presence.

These are fictional design directions. Final character sheets should define each character's role in the learning ensemble, not personal-life details.

Before the first prototype, each character must have:

- a name;
- a STEAM emphasis;
- a recurring explanation role;
- a concise public-safe biography;
- a visual prompt sheet;
- a voice prompt sheet;
- a continuity checklist;
- explicit negative constraints against real-person imitation and stereotype-driven writing;
- and a personal-life boundary that prevents scripts from discussing dating, relationships, family, or private biography unless explicitly approved.

## Media-Type Requirements

The production system should be able to create or coordinate:

- generated characters;
- generated voices;
- visages for video, image, and animation;
- narration;
- web navigation tutorials;
- finished videos;
- charts;
- markdown formulas or paragraphs used as production inputs;
- images;
- animations of concepts;
- and recurring `Educators`.

## Platform Requirements

The first priority media platform is:

- YouTube 4K HD landscape, with a 16:9, 3840 x 2160 export target.

Later platform profiles are:

- TikTok;
- Architrino webapp.

Each platform profile should eventually specify:

- aspect ratio;
- duration bands;
- caption and transcript requirements;
- thumbnail or cover-frame requirements;
- file formats;
- source-artifact retention;
- publication checklist;
- and whether the asset is public, internal, tutorial-only, or app-embedded.

## Terminology Requirement

Use `Educators` for recurring instructional characters.
