## Shared Display Runtime Corrections

On 2026-07-22 the operator accepted a shared Borg correction discovered during A1 review: prescribed Display branches now use the selected record's `responseCenter` and `sphericalEnvelopeRadius` instead of requiring that radius to equal the random-workspace manifest radius. The former equality check prevented Display-branch construction for ordinals 1–11 and 16–17; ordinals 12–15 passed only because their declared radius happened to equal the manifest radius. Borg now applies the record-owned envelope consistently to branch construction, coordinate scaling, the boundary guide, camera fitting, and escape diagnostics while retaining the manifest envelope for the random workspace.

This is a display-runtime correction shared mechanically across the catalog. It changes no canonical member definition, source specification, generated Borg record, source hash, or generated-record hash. It therefore causes no analytical-source invalidation and requires no analytical packet or database quarantine. Every later candidate remains `pending`, and A1 remains `in-review`; successful branch construction is not candidate sign-off and gives no EOM-solver retention, stability, energy, binding, or physical-realization conclusion.

On 2026-07-22 the operator accepted a second shared prescribed-display correction during A1 review: orbital trails use one neutral light-purple color while the endpoint markers retain their polarity colors. The rule applies to every prescribed catalog replay so trail color does not imply that a prescribed path itself has polarity. If the operator starts the optional Display simulation branch, Borg returns to polarity-colored evolved path-history trails because those rows are no longer the prescribed orbital depiction.

This color correction is display-only. It changes no prescribed coordinates, canonical member definition, source specification, generated Borg record, or analytical source. It invalidates no analytical packet or database artifact, and later catalog candidates remain `pending` until individually reviewed.

On 2026-07-22 the operator also selected four-times display-only oversampling for prescribed cubic-Hermite replay. Borg now evaluates each existing cubic segment at one quarter of the record's declared display interval before passing the resulting rows to the unchanged straight-segment trail renderer. The source specification, generated record bytes, cubic coefficients, declared error bounds, and record hashes remain unchanged; the additional rows are viewer samples and have no analytical or EOM-solver authority. EOM-evolved and random histories retain their own sampling intervals.

This shared replay correction invalidates no source, generated record, analytical packet, or database artifact. It would be falsified if a prescribed replay used fewer or more than four display subintervals per recorded interval, if any sampled row disagreed with evaluation of the stored cubic segment at the same time, or if the record bytes or hash changed as a consequence of viewing it.

On 2026-07-22 the operator restored Borg's orthographic appearance after confirming that every prescribed circular orbit lies in the plane orthogonal to its source-defined binary axis. Borg now uses one orthographic camera for prescribed replay, optional Display evolution, and the random workspace. Envelope fitting sets the orthographic frustum from the active record-owned or manifest-owned envelope, viewport aspect, and fit margin; mouse-wheel zoom changes the frustum scale rather than moving a perspective camera through depth.

This shared rendering correction changes no taxonomy definition, prescribed coordinate, source specification, generated Borg record, source hash, generated-record hash, or analytical source. It therefore invalidates no analytical packet or database artifact. It would be falsified if equal-size objects at different camera depths acquired different screen sizes, if a viewport aspect change clipped the fitted envelope, or if camera rotation failed to project a circular path into the corresponding orthographic ellipse.

On 2026-07-22 the operator selected the mutually orthogonal near-rest endpoint for every Family-A Borg candidate. All eleven Family-A catalog specifications now use $\lambda_A=0$, the declared $x$, $y$, and $z$ binary axes, and the corresponding yz, xz, and xy orbit planes. The correction changes no candidate id, label, radius, axial half-separation, transverse orbit radius, frequency, phase, circulation sense, polarity assignment, group center, or translation.

This is a shared prescribed-source correction, not a rendering-only change. Ordinals 2–11 receive new specification, Borg-record, and exact prescribed-source hashes. No repository JSON analytical packet or database artifact references the superseded hashes, so the repository impact is source/display supersession rather than analytical-packet quarantine.
