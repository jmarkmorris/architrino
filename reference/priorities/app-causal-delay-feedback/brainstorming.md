## Ideas And Insights

- Pedagogical direction: the app should make causal delay apparent before it asks users to tune controls. The central lesson is that an architrino is not responding to where the other architrino is now; it is responding to a causal signal that left from where the other architrino was earlier. A guided `Story` mode should present one emitted wake, one reception event, and one line back to the emission point before opening the full sandbox.
- Lower-age teaching path: use prediction before explanation. Pause before a reception, ask the user to identify where the influence came from, then reveal the expanding wake and the old emission point. The goal is for even a young user to say, in plain language, "the effect came from the past."
- Suggested first Story sequence: one architrino sends expanding wakes; the other receives one wake; both move so wakes come from old positions; changing causal speed changes which old point matters; dragging the path shows causal history recomputing.
- Audience layers: preserve the same simulation while changing the explanation level. For younger readers, use "a ripple takes time to travel." For middle-school readers, "the other dot feels the signal only after it arrives." For older readers, "the interaction depends on delayed position, not current position." For theory-facing use, connect the visual to path-history dependence through causal-delay roots.
- Existing outreach context: this causal-delay idea has already started being taught through the children's book series. The app should become the interactive companion to that thread: simple enough for the book audience, but still faithful enough to introduce the deeper solver and path-history concepts later.
