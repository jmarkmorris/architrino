## Architecture Summary

State ownership is clean and single-homed: `PhotonRuntime.js` holds the canonical state in a closure and is the only module that reassigns it; every mutation funnels through `normalizePhotonState()` (`PhotonStateRuntime.js`), which clamps/locks everything (radii ordering, power-of-two frequencies, locked roles/directions). Controls mutate the live state object then call `onStateChange`, which re-normalizes — mutate-then-normalize rather than immutable updates, but consistently applied. No circular imports, no hidden persistence, no innerHTML in the photon modules (markdown HTML goes through the shared `MarkdownRuntime` with `markdown-it({html:false})`).

Dependency sketch: `main.js → PhotonRuntime`; `PhotonRuntime → State/Preset/Search/Controls/Formula/Diagnostics/BraidVisual + PrescribedPathAnalysis (id only) + MarkdownRuntime + StandaloneAppHome`; `FormulaRuntime → PrescribedPathAnalysis, StateRuntime, TransmitterHistoryRuntime`; `SearchRuntime → State/Preset/Diagnostics/Formula`; `SelfHitSweepRuntime` is harness-only (not wired to the UI); all remaining modules depend only on `StateRuntime`.

The split is mostly coherent, with two caveats: `PhotonFormulaRuntime.js` conflates five concerns (request builders, root-solve adapters, field superposition, polarization fitting, self-hit phase-family classification) and should be split; `PhotonRuntime.js` owns too much unrelated state (solver snapshot cache + search-result store + preset store + markdown). Evidence discipline is good: every analysis record carries `evidenceGrade: "display-only-visualization" / nonEvidence: true` via `PHOTON_TRANSMITTER_HISTORY_BOUNDARY` (`PhotonTransmitterHistoryRuntime.js:13-22`), and the field path fails closed without causal-factor records.

## HIGH Findings

### H1 — The "Electric Field" plot is a single-harmonic fit reconstruction, not the computed field — and the default configuration guarantees the fit is wrong (verified numerically)

`PhotonRuntime.js:374-419` (`createPhotonRuntimePlotFromPolarizationTrace`) builds the plot by evaluating the polarization fit's fundamental coefficients. The fit (`PhotonFormulaRuntime.js:2457-2557`) targets only the reference frequency (M layer, 2 Hz) over one middle cycle, from 6 samples in the live app (`polarizationSampleCount: 6`, `PhotonRuntime.js:69`). The default state has layers at 4/2/1 Hz; the 1 Hz component is not orthogonal to the fundamental over a single 2 Hz cycle. Verified: for `ey = cos φ + cos(φ/2)` the fitted fundamental amplitude is 1.55 at n=6 and still 1.32 at n=144 vs true 1.0 — a structural leak, not a sampling artifact. So the panel titled "Electric Field" with "Max E" shows a pure sinusoid with inflated amplitude regardless of the actual field; the contaminated fundamental also feeds the ellipse, Stokes rows, and classification label. The accurate sampler `buildPhotonPlotSamplesWithPrescribedPathAnalysis` (`PhotonFormulaRuntime.js:2627-2670`, 360 real samples) exists and is never called by the app — only by tests. Fix: drive the plot from the real sampler (or overlay raw samples and relabel "Fundamental fit"), and widen the fit window to the slowest enabled layer's cycle (frequencies are powers of two, so a common period exists).

### H2 — "Helicity estimate" diagnostic is a constant

`PhotonDiagnosticsRuntime.js:235-237` computes helicity as `left.direction === "ccw" && right.direction === "cw" ? 1 : 0`; `normalizeBraidState` (`PhotonStateRuntime.js:325-341`) hard-locks left→ccw, right→cw for every state (verified: flipping and normalizing restores the lock). Every configuration — including the linear-polarization preset and any import — reads "Helicity estimate +1 / good". A constant presented as a graded physical estimate is a counterfeit diagnostic and, given the repo's claim-grading stance (no validated photon), a UI overclaim. Fix: derive from the fitted `s3` sign (already computed) or delete the row.

### H3 — Search-state races: concurrent searches and import-vs-search clobber

`runConfigurationSearch` (`PhotonRuntime.js:775-804`) has no in-flight guard and no generation token: two clicks run two full searches concurrently, and `searchResults = await ...` (788) replaces the whole array on completion. Any `importSearchResults` (919-937, prepends), rename, delete, or selection toggle performed while a search runs is silently discarded when it resolves; preview state can be restored into a list that no longer contains the previewed result. Fix: `searchGeneration` counter (mirror the solver-snapshot pattern at 558-569), disable the button while in flight, merge or reject rather than assign.

### H4 — Analyzer readout trio is systematically wrong: residual compares two different estimators; "cycle average" is a 2-sample mean (verified numerically)

Instantaneous fraction is `projection²/(|E|²+ε)` (`PhotonFormulaRuntime.js:2240-2242`); `computePhotonAverageAnalyzerFraction...` (2559-2578) averages that ratio over time; but `analyzerFractionTarget` (2416-2420) is `⟨p²⟩/⟨|E|²⟩` — a ratio of averages. `analyzerResidual` (2599-2600) therefore has a nonzero definitional offset for any non-circular, non-degenerate state: verified exactly −0.133 / +0.133 at analyzer 0°/90° for Ay=1, Az=0.5, δ=90° with perfect math. And the live app averages from 2 samples (`analyzerSampleCount: 2`, `PhotonRuntime.js:71`) over the 3-cycle run, so "cycle average" and "analyzer residual" rows are noise plus built-in bias presented as solve quality. Fix: use the same estimator on both sides (energy-weighted `⟨p²⟩/⟨|E|²⟩` is the standard transmitted fraction) and raise the sample count or relabel.

### H5 — Per-frame DOM rebuild + KaTeX typesetting inside the RAF loop

`frame() → draw() → syncOutputs()` runs every animation frame (`PhotonRuntime.js:1008-1019, 694-715, 685-692`); `syncOutputs` unconditionally rebuilds ~30 diagnostics rows and ~18 formula rows (`container.textContent = ""` then recreate, including ~10 `katex.render` calls) at up to 60 fps even when the solver snapshot is unchanged — defeating the solver-throttling machinery. Fix: cache last-rendered snapshot identity (stateKey + solveTime) and re-render the panels only on change; the time/cycle outputs can update per frame cheaply.

## MEDIUM Findings

- **M1 — Solver-error retry storm.** On rejection the catch sets `solverError` and calls `draw()` (670-682); `draw` reschedules, and null snapshot ⇒ `stateChanged` ⇒ the 750 ms throttle is bypassed (615-622) — full field solves retried every frame with no backoff. Apply the throttle when `solverError` is set or add backoff.
- **M2 — Contribution/root index-pairing mismatch in the absolute-history path.** The kernel emits roots ascending in emission time (`PrescribedOrbitCausalRoots.mjs:535-559`); the app re-sorts each root set ascending by delay (`PhotonFormulaRuntime.js:2093-2101`) then merges the library's observer-field contributions by array index (1716-1719), which follow the unsorted order. With ≥2 roots per transmitter (routine — the default I layer runs at 1.2 c_f), merged records combine root A's identity/phase with root B's electric/delay/jacobian. Vector totals are unaffected and the UI shows only aggregates, so it is latent — but search scoring already exports contributions structurally. Fix: key by `(transmitterRootRequestIndex, transmitterRootIndex)` or sort after merging; add a multi-root pairing test.
- **M3 — Incomplete destroy / unsafe re-init.** `destroy()` (1085-1095) removes only keydown and resize; the click listeners from `init()` (1052-1077) persist, so a second `init()` double-fires everything; two concurrent RAF loops result (1081, no guard). `createSeparationLogControl` registers a document-level click listener (`PhotonControlsRuntime.js:534-538`) never removed and re-registered on every controls rebuild. Fix: AbortController signal, a controls-runtime `destroy()`, an init re-entry guard.
- **M4 — Import accepts arbitrary JSON silently; exported selection state discarded.** `parsePhotonSearchResultsJson` (`PhotonSearchRuntime.js:969-977`) never checks the `kind`/`version` it exports (944-948); any array-shaped JSON becomes N "Imported" entries whose state is clamped defaults, indistinguishable from real configurations. No XSS exposure (all rendering is textContent; grep-verified no innerHTML) and state is fully clamped, but silent garbage is a provenance hazard. `importSearchResults` also forces `selected: true`, discarding exported flags; same-millisecond imports can duplicate ids and `deleteSearchResult` then removes both. Fix: validate `kind`, preserve `selected`, monotonic id counter.
- **M5 — Softening inconsistent between history modes.** Co-moving path clamps distance ≥ 0.08 (`MIN_FIELD_DISTANCE`, `PhotonFormulaRuntime.js:36, 191-197`); the absolute-history library path floors at 1e-12 (`PrescribedPathAnalysis.mjs:405`). The default observer (origin) sits within ~0.016–0.11 of the inner-layer transmitters — inside the co-moving softening radius — so toggling "Absolute transmitter history" changes the softening law and "Max E" can jump orders of magnitude. Fix: pass a shared min-distance through `observerFieldRequest`; document it.
- **M6 — Controls `sync()` is an index-walk over a parallel array** (`PhotonControlsRuntime.js:1196-1250`): a manual index must match construction order across five sections; any inserted control silently shifts later bindings, and nothing pins it (tests never instantiate the controls runtime). Fix: keyed map registration.
- **M7 — "Phase spread" metric mislabeled.** `computePhaseLockSpread` (`PhotonDiagnosticsRuntime.js:17-27`) measures deviation from a 120° gap target, so identical phases (the default) display "Left phase spread 160.0 deg". Rename ("120°-spread error") or use the circular-spread function already in the file (29-44).
- **M8 — β/γ symbol discipline.** `PhotonControlsRuntime.js:1077` labels the Lorentz-factor slider "Local γ" (bare γ as Lorentz factor at app level; ratified convention wants channel-subscripted forms) and 1090 labels translation speed "Photon cγ/c_f" — a photon subscript γ directly under a γ-as-Lorentz-factor slider. Search candidate names "Local c gamma 2/5/20/100" (`PhotonSearchRuntime.js:163-167`) repeat it. Positive: no "retarded", no mass/force at architrino level anywhere in the app (grep-verified). Fix: "Lorentz factor γ⋆" and "Photon speed c_γ/c_f" with typography that keeps the two γs apart.
- **M9 — Dead code and dead options** (grep-verified no app call sites): `absoluteHistorySegments` option consumed only by `createPhotonAbsoluteTransmitterSegmentCausalRootRequests` (`PhotonFormulaRuntime.js:1220-1267`) which nothing calls — the comparison solve silently ignores the segment budget it advertises; `dedupePhotonDelayedRoots` (1556-1569) uncalled; `hasPhotonInlineSolverOption`, `PHOTON_RUNTIME_SOLVER_MEMORY_BUDGET_BYTES` dead; `createPhotonRuntimeSolverOptions` pointlessly async; `getPhotonFieldPlotSampleCount` test-only; `state.time.cycleCount`/`cycleReferenceLayer` in schema and solver key with no UI control (and `getPhotonMiddleCycleBounds` would exceed the run at `cycleCount: 1` via import). Delete or wire up.
- **M10 — Main-thread solve cost and search freeze.** One snapshot = 10 synchronous full-field solves × 12 transmitters plus full self-hit diagnostics (span run + 12 helical root solves) every 750 ms while playing (the interactive options never set `skipSelfHitDiagnostics`; `PhotonFormulaRuntime.js:2601-2610`). `runConfigurationSearch`'s `setTimeout` only defers the start; the 6-candidate evaluation (summary + perturb + dual-mode comparison incl. helical records) then runs synchronously — a multi-second UI freeze. Fix: `skipSelfHitDiagnostics: true` for the interactive snapshot (refresh diagnostics on slower cadence); chunk or worker-ize the search.
