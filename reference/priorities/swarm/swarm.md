## Current Terminology

The active reader-facing swarm terms are:

| Term | Working meaning |
| --- | --- |
| `Noether swarm` | The overall class of Noether-constrained swarm models. Use `Noether Swarm` only in titles, headings, scene titles, and other title-case labels. |
| `neutral swarm` | The broad six-architrino neutral case before any required binary grouping or radial organization is assumed. |
| `shell swarm` | A neutral swarm whose six architrino paths remain in a controlled radial support band. |
| `nested shell swarm` | A shell swarm with three ordered radial support bands. |

Formula notation currently uses $\rho_{\text{NS}}$ for physical Noether swarm density and $\Lambda_{\text{NS}}$ for the reduced nested shell swarm closure label. Other formula symbols with legacy `core` subscripts, including $R_{\text{core}}$, $\omega_{\text{core}}$, $Q_{\mathrm{core}}$, and $\mathcal{F}_{\text{core}}$, remain compatibility symbols unless a separate approved row renames them.

The completed terminology migration table is archived in [swarm-migration-archive.md](swarm-migration-archive.md).

Notes: this should state the required rows of $\mathfrak{R}_{\mathrm{neutral}}$ and make every later swarm variant a case reduction rather than a separate ontology.

3. `neutral_swarm_finite_mode_search` — Create the first executable finite-mode search target for a free-support neutral swarm with hollow support, bounded speed factors, and all-pairs delayed force rows. Status: `open`. Notes: this tests whether the generalized model has a live branch outside the old binary-partition assumptions.
4. `bounded_speed_coupled_fixed_point_system` — Make the coupled bounded-speed residual $\mathcal{R}_{\mathrm{cpl}}^\nu$ the next solve object rather than treating speed, root, support, action, and force rows as separate diagnostics. Status: `open`. Notes: branch evidence is not promotable until curves, speed factors, root sheets, support variables, action scale, and event variables close on one live ledger.
5. `support_complete_m3_tail_resolution` — Continue the existing exact-antipodal $M=3$ path until the support-tail ledger is excluded or assimilated. Status: `open`. Notes: this is the nearest existing route to a rigorous retained or rejected branch, but it remains active-window-only until tail, action, event, and stability rows are closed or explicitly failed.
6. `shell_swarm_reduction_row` — Formalize shell swarm as a case reduction of neutral swarm. Status: `open`. Notes: required rows include common support band, small radius spread, support multipliers, support work, occupancy rows when containment is claimed, and no hidden fixed-radius assumption.

## Operating Rules

- Use the accepted terminology above in new priority prose.
- Treat priority-only labels from older packets as history, not active taxonomy.
- Use `slot` and `sector` only in standard mathematical usage.
- Use `binary` for one binary in a nested shell swarm; in that context each shell contains a binary.
- Do not promote retained-branch claims, observer exports, or model-closure claims until the live ledger/certificate rows close.
