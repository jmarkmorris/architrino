## Purpose

This priority tracks emerging standards and guidance for how AI systems communicate with people, label AI-generated material, preserve source and provenance signals, explain limitations, and report service status without confusing users.

The goal is early adoption where it improves trust, interoperability, accessibility, compliance, or user understanding. The goal is not to import technical standards language into ordinary user-facing prose.

## Plain-Language Rule

User-facing text should explain the user-visible behavior first:

1. what the user will see;
2. what the system will do;
3. what the system will not do;
4. what the user controls;
5. what is private, retained, public, paid, generated, or source-grounded;
6. what happens when a provider, payment, speech, image, accessibility, or status dependency fails.

Technical standard names may appear after the plain explanation when they are useful for implementation, compliance, or interoperability. They should not replace the explanation.

Example:

| Prefer | Avoid as ordinary prose |
| --- | --- |
| Show that an image was generated by AI and keep a verifiable record of its origin when possible. | Emit provenance assertions through a media credential surface. |
| Tell the user when they are talking to AI, what data is retained, and what actions need confirmation. | Satisfy transparency and account-policy gates. |
| Use safe status messages that explain outages without exposing private prompts, secrets, or raw provider logs. | Publish observability refs. |

## Research Targets

Evaluate emerging standards and guidance in these areas:

1. AI disclosure: when the interface should tell users that they are interacting with AI or viewing AI-generated material.
2. Generated-media labeling: how images, audio, video, diagrams, and edited media should carry visible and machine-readable origin information.
3. Source and provenance: how to preserve where an answer, artifact, or media item came from without implying proof status.
4. User control: how to explain consent, confirmation, spending, retention, deletion, export, and public sharing.
5. Risk and incident communication: how to report limits, degraded service, outages, refusals, and safety blocks in normal language.
6. Accessibility: how labels, captions, transcripts, alt text, and explanations should work for assistive technology.
7. Model and service documentation: how model cards, system cards, AI management standards, risk frameworks, and public status pages should inform Archie service disclosure.
8. Agent and tool communication: how future AI-agent protocols should be adopted internally without leaking protocol vocabulary into reader-facing text.

## Current Standards To Monitor

Use official sources first and refresh this list before implementation decisions:

1. [NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) for trustworthy AI risk practices and generative-AI risk profiles.
2. [ISO/IEC 42001](https://www.iso.org/standard/42001) for AI management-system requirements.
3. [C2PA specifications](https://spec.c2pa.org/specifications/specifications/2.4/index.html) and Content Credentials for media provenance and user-experience guidance.
4. [EU AI Act guidance](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai) for transparency, AI-generated-content labeling, and general-purpose AI obligations that may influence global product expectations.
5. Accessibility guidance and legal requirements that apply to captions, transcripts, alt text, controls, and status communication.
6. Security and privacy guidance for prompt privacy, generated media, provider data use, logs, support records, and public issue handoff.

## Adoption Standard

Adopt an external standard only when it satisfies all of these:

1. it improves user understanding or trust in a visible way;
2. it can be explained in normal language;
3. it does not inflate source authority or proof status;
4. it does not require storing private prompts, private media, secrets, or raw provider payloads beyond the stated retention policy;
5. it has a practical implementation route for the future Archie service;
6. it can fail closed with a plain explanation when unsupported.

## Output

The first pass should produce:

1. a short standards landscape report;
2. an adoption recommendation table: adopt now, monitor, defer, or reject;
3. plain-language copy rules for AI disclosure, generated media, service status, privacy, cost, and action confirmation;
4. implementation notes for any machine-readable labels, provenance metadata, status records, or accessibility requirements;
5. a list of terms that may appear only in implementation/schema material, paired with the normal user-facing phrase.
