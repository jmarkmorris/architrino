# Provider-aware bounded evolution transport

This implementation contract extends the [reviewed provider design](equation-provider-design-v1.md). The frozen [canonical v1 contract](evolution-contract-v1.md), Borg v1 framing and canonical v7 checkpoint format remain their own interfaces. The [Stage C qualification record](../analysis/equation-provider-stage-c-2026-10-11.md) owns measured implementation scope, review, commands and falsifiers. This contract supplies consumer transport and persistence; it supplies no interacting 3:3 scientific acceptance or Surface app.

## Selection and admission

The EOM solver remains the forward engine. Its registered compositions are `canonical/v1` and `canonical-surface/v1`. Selection defaults to canonical interaction, unrestricted speed, no constraint and numerical execution. A Surface request explicitly selects the surface composition, `constraint: surface` and a fixed supported geometry. Analytical execution, arbitrary stage graphs, dynamically loaded providers, Surface joint/event charts and new ceiling-response laws remain unavailable.

Use numerical $c_f=1$. The implemented speed domains are unrestricted, inclusive $\|\mathbf V\|\le1$ and strict $\|\mathbf V\|<1$. Unrestricted uses `boundaryPolicy: none`; inclusive and strict require `boundaryPolicy: halt`. These policies select admission and publication checks, without changing canonical acceleration contributions, self accounting or velocity. The existing inclusive response-factor specification is a separately defined interaction modification and is not activated here.

Admit the whole prepared history and every proposed published dense extension. The speed certificate includes retained velocity uncertainty. Exact constant velocity uses rational squared norm, including multiaxis equality; a proven circular-factory prefix uses its exact speed certificate, while computed suffixes use interval subdivision. Unresolved cells fail closed. The speed instrument stops unresolved subdivision at depth 24 or a cumulative 200,000-cell counter; already-certified cells can still pass beyond that counter, so it is not a strict total-visit cap. Inclusive mathematical equality can still be uncertifiable for a general error tube. A failed attempt returns the preceding accepted prefix and attempted time interval as possible boundary/uncertainty coverage; it is not an exact first-contact location or a continuation response.

Surface retains the Stage B ordinary sharp chart: certified circular preparation, coherent subwake paths, fixed sphere/oblate/ring-torus geometry and strictly past partner roots. Therefore inclusive speed equality does not establish a supported forward Surface chart. The independent constrained-publication gate remains required under every speed selector.

## Request and transport

`eom_borg_shadow_cli eom-v2 [--checkpoint-file PATH]` consumes one bounded JSON document on stdin and writes one final JSON response on stdout. `eom-v2-server` consumes one document per line. Readiness and accepted-step progress use stderr schemas `eom_ready/v2` and `eom_progress/v2`. Cooperative `SIGUSR1` cancellation is installed before readiness; consumer adapters queue cancellation until that event. A checkpoint path is a trusted launcher argument, never a request field.

Wire envelopes select `capabilities`, `inspect`, `evolve` or `resume`. Capabilities takes only `operation`; inspect/evolve take `operation` and `request`; resume additionally takes `checkpoint` and string `endTime`. The parser-only `validate-cancel` operation validates a control envelope without running dynamics. Unknown fields, duplicate decoded keys including escaped aliases/empty keys, wrong types and unsupported selections reject in the maintained C++ parsing boundary.

The scientific request schema is `eom_evolution_request/v2`. Decimal quantities use strings; counters and budgets use nonnegative integers within JavaScript's exact integer range. Top-level fields are `schema`, `runId`, `model`, `interval`, `paths`, `numerics` and `resources`. Run/path identities contain 1–1024 bytes. Evolve/resume require explicit run identity, interval and nonempty population; inspect may omit histories and then makes no preparation-admission claim.

| Field | Implemented content |
| --- | --- |
| `model` | `compositionId`, `speedDomain`, `boundaryPolicy`, `constraint`, `method`, `fieldSpeed`, `coupling`, optional `geometry`. |
| `geometry` | `kind`, `radius`, `flattening`, `majorRadius`, three decimal `center` coordinates and a decimal 3×3 orthogonal `orientation`. Surface kinds are `sphere`, `oblate`, `ring-torus`. |
| `interval` | Decimal `start` and `end`; original preparation ends at the selected start. |
| `paths` | Ordered objects with `pathId`, decimal `charge` and `history`. |
| Cubic history | `kind: cubic`, nonempty `segments`, each with `start`, `end`, three rows of four decimal `coefficients`, three `positionErrors` and three `velocityErrors`. |
| Circular history | `kind: uniform-circular`, `start`, `end`, `maximumSegmentStep`, `radius`, `height`, `angularSpeed`, `speed`, `phase`, optional `tiltX`/`tiltY`. This constructs provenance-bound preparation, not a future evolution curve. |
| Decimal numerics | `initialStep`, `minimumStep`, `maximumStep`, `rootTolerance`, `transmitterFactorFloor`, `accelerationTolerance`, `positionTolerance`, `velocityTolerance`, `correctionTolerance`, `adaptiveSafety`, `adaptiveMinimumScale`, `adaptiveMaximumScale`, `surfacePositionTolerance`, `surfaceTangentVelocityTolerance`. |
| Integer numerics | `rootMaxDepth`, `rootMaxCells`, `maxCorrectionIterations`, `maxStepAttempts`, `maxRejectedSteps`, `threadCount`, `surfaceMaxDepth`, `surfaceMaxCells`. |
| Boolean numerics | `adaptiveGrowth`, `continuousAdaptive`. |
| Resources | `memoryBytes`. Default 1 GiB; maximum 2 GiB. The host estimate is an admission allowance, not a measured resident-set bound. |

The wire limit is 32 MiB with JSON depth 64, population 1024 and combined history budget 100,000 segments, reduced further by the memory allowance before factory allocation. Circular duration/step is checked using exact rational arithmetic and the factory's binary evaluation before generating segments. Control maxima are root depth 1024/cells 2,000,000, correction iterations 100, step attempts/rejections 10,000, threads 32, Surface depth 64/cells 2,000,000. Existing host validation may reject sharper domains or nonpositive controls.

The local dev server exposes `/api/eom/v2/capabilities`, `/inspect`, `/evolve`, `/resume`, `/cancel` and `/checkpoints/<id>`. Inspect/evolve bodies are scientific requests; resume takes the full wire envelope. Cancellation uses `{runId, executionId?}`. Browser launches carry an opaque generation in `X-EOM-Execution-Id`; an overtaking cancellation is queued only for that generation, and the browser repeats it until the operation terminates. A run-ID-only cancel targets an active worker and cannot attest durable coverage. Bounded parser-only control invocations validate cancellation separately from the four watched scientific workers. Workers have a 120-second default execution deadline, followed by bounded cooperative/termination grace. HTTP upload precedes worker admission.

The consumer-neutral Node and browser clients reuse the same EOM executable; Borg also uses the shared JSON POST/error adapter. Borg's retention, grading and catalog policy remain with its existing consumer. Browser disposal prevents launch after pending inspection and drains active operations to their terminal durability receipt or explicit error. Local service shutdown drains watched workers before exiting. These are process/transport guarantees, not a physical acceptance gate.

## Response and provenance

Inspection returns `eom_inspection/v2`, `resolvedModel` and `modelDigest`. Evolution returns `eom_evolution_response/v2`, contract ID `eom_evolution_contract/v2`, matching model/digest, cumulative counters, accepted coverage, only the newly accepted `publishedExtensions`, and an explicit halt record. Decimal intervals and quantities remain strings. `ledgers` include atomic attempts, complete point-root/self accounting, whole-slab partner roots and Surface solution/error/geometry certificates. Surface diagnostics report receiver-superposed net interaction, tangent interaction, discarded normal, curvature, support and total acceleration; there is no per-hit discarded-normal ledger.

`evidence` distinguishes numerical acceptance, artificial confinement and `scientificAcceptance: false`. The persisted checkpoint contains full retained histories; response extensions start at this invocation's accepted-start time. A resumed invocation does not replay old curves as newly generated paths. Parser/admission failures return `eom_error/v2` with a named code and message.

## Persistence and restart

`eom_provider_checkpoint/v8` binds the resolved model, definition/build receipts, original preparation, selected domains, numerical/resource controls, run identity and adaptive controller state. Resume retains the same original request and supplies an extended end separately; changing its identity or preparation requires a separately designed branch operation. The manifest's source/configuration receipt inventories authored EOM source, compiler bytes, named numerical libraries/entry headers and settings. Boost's receipt covers the linked JSON library, entry headers and version, not all transitive headers or SDK bytes; it is descriptive source/configuration identity, not an executable-byte hash or authentication signature.

Canonical state embeds existing v7 bytes within the new envelope; v7 alone rejects selected restricted domains and Surface. Restore compares inner canonical model/run/population, original preparation prefix and analytical provenance, all inner/outer histories and controller state. New v8 entry points reject typed joint preparation until its affine coefficients/errors/symbol registry have a declared binding; the existing v7 owner retains its supported joint route. This checks persistence consistency and accidental/tamper detection; a resealed malicious canonical future is not independently re-solved merely because its checksum is valid. Trailing rejected attempts remain in the response ledger while the embedded checkpoint stores only the accepted prefix and cumulative controller counters.

Surface state retains chronological publication boundaries and full cubic/error records. Restore starts from the original preparation, revalidates every recorded publication through the existing integral-map gate and reconstructs immutable true-acceleration carriers. It compares all uploaded segments, including original prefix and any tail, and rejects a reconstruction that would change coefficients or errors. Counters must agree with chronology. Uploaded booleans cannot certify a Surface history. Persistence also checks population, endpoints and immutable carriers before writing; resumed histories and carrier storage enter the working-set estimate.

The shared atomic writer fsyncs a temporary file, renames it and fsyncs the directory. `checkpoint.durable: true` is returned only after those operations succeed; the Node client rereads its server-owned UUID record and matches the receipt. Storage failure returns accepted coverage with `durable: false` and `storageFailure`. A cancellation acknowledgement merely requests a stop; the terminal response supplies the durable accepted boundary or explicit failure. Interruption before durable publication cannot authorize an unrecorded continuation.

Checkpoint creation reserves the encoded original request plus 8192 bytes for the resume envelope/end token within the same 32 MiB parsing budget. An expanded preparation or retained history exceeding that symmetric limit is not written. Evolution still returns its accepted coverage, `durable: false`, `data: null` and `checkpoint_size_exhausted` in the storage-failure record. This limit can stop persistence before the population/segment admission limits are reached.

## Bounded record consumers

Retained-record HTTP calls may opt into `X-EOM-Checkpoint-Mode: reference`; the process-client projection option is `checkpointMode: 'reference'`. Default inline presentation is unchanged. Unsupported values and reference mode on non-record operations reject before launch. For a durable server-owned checkpoint, the view retains its schema, digest, accepted time and UUID, replaces redundant `data` with null, and adds `retrieval: solver-host` plus the existing checkpoint retrieval URL. The full checkpoint and original response stay retained on the host. Resume fetches the full checkpoint and preserves original-preparation, model and controller validation. This is a presentation choice outside scientific request identity; it changes no numerical policy or solver output.

The [Stage E record](../analysis/equation-provider-stage-e-2026-10-11.md) adds opt-in local-service `POST /api/eom/v2/evolve-record` and `/resume-record`, with the same scientific request/resume envelope and C++ evolution operations. Original direct routes retain their framing. `GET /progress?runId=...` returns the last observed active-worker progress or null; it is not a durable receipt. `GET /records/<UUID>/raw` streams a completed retained response. The qualified-sphere endpoints project/stream only the exact retained Stage D request/response hashes when present on that host; missing originals are explicit unavailability.

Record workers count and write stdout bytes up to 256 MiB into UUID raw files. Partial overflow/nonzero/parser/storage failures retain evidence and return `retainedFailure` with record ID, bytes, recorded checkpoint time/ID when available and `completeExport:false`. Mere checkpoint existence does not attest durability. Four workers and a conservative 2 GiB record-directory admission allowance apply; each retaining worker reserves its raw maximum plus 8192 completion-marker bytes, and existing evidence is not deleted. Whole-document parsing remains bounded by the raw allowance; serialized/disk bounds do not assert a small heap or peak resident-set bound.

A successful projection preserves complete `publishedExtensions`, complete checkpoint, full resolved model/evidence, sampled receiver-total interval diagnostics and `record` metadata: raw bytes/hash/link, diagnostic counts, ledger counts and accepted Surface certificate/geometry summaries. Full raw ledgers are omitted from the view and retained in the artifact. Surface diagnostic sampling uses a per-member stride retaining up to 128 samples plus the final row and is never interpolated as instantaneous data. Rounded geometry summaries do not replace original certificates. Projection is limited to 12 MiB. Raw file, completion marker and containing directory are fsynced before the complete artifact receipt; downloads require a complete marker and matching byte count. Encoding completeness is distinct from calculation completion or scientific acceptance.

A halted/cancelled response can retain a certified accepted prefix even when the invocation's overall numerical evidence status is `failed`. Consumers must display the accepted prefix, certificate summary and halt reason together, without treating the invocation as completed. Zero accepted coverage supplies no future playback. Resume still requires a durable checkpoint and the existing original-preparation/model revalidation. Browser record/model matching and validation failure retain the artifact/checkpoint receipt rather than losing the evidence pointer.

Surface's own `surface_playback_record/v1` combines original request, result parts and declared provenance within 12 MiB serialized bytes. Its imported provenance is unverified; EOM owns continuation validation. The 48 MiB serialized session allowance is a consumer memory-admission policy, not a scientific retention or peak-memory guarantee. Complete raw records/checkpoints remain server-owned. These presentation schemas do not modify frozen canonical v1/v7 contracts or define a new equation.
